# Luna への委譲

Codex には、ツール呼び出しを強制ブロックする仕組みがない。ここに書くのは
「毎回自分から実行する運用ルール」であり、強制ではない。それでも効果は大きい。
数百行のファイルをそのまま読むと、その内容はスレッドが終わるまでコンテキストに
残り続け、以降のすべてのターンで課金対象になる。読む作業自体を使い捨ての子
コンテキストに追い出せば、残るのは要約1回分だけになる。

## 読み込みを委譲する場合

数百行を超えるファイル、あるいは複数ファイルを横断して1つの問いに答える必要が
あるとき、自分で `Read`/`rg` を連発する前に子エージェントへ投げる。

```
spawn_agent {
  fork_turns: "none",
  model: "gpt-5.6-luna",
  reasoning_effort: "medium",
  prompt: "<絶対パス> を読んで、<具体的な質問> に答えて。
           該当箇所は file:line 形式で示すこと。
           答えが見つからない場合は、探した場所を含めて『見つからない』と
           明言すること。ファイルの内容をそのまま貼り返さないこと。"
}
```

明確で具体的な質問を渡すこと。曖昧な依頼は曖昧な要約になって返ってくるだけで、
結局読み直すはめになりコストが二重にかかる。

短いファイル、正確な編集のために生テキストが要る場合、範囲がすでにわかっている
場合は委譲しない。直接読んだほうが速い。

## コード生成を委譲する場合

設計がすでに決まっていて、あとはタイピングだけの作業 — ひな型、テストの雛形、
fixture、複数ファイルにまたがる機械的な変更 — も同様に委譲する。

```
spawn_agent {
  fork_turns: "none",
  model: "gpt-5.6-luna",
  reasoning_effort: "medium",
  prompt: "<近傍の既存コードの参照先> のスタイルに合わせて、<具体的な仕様> を
           <出力先パス> に直接書き込んで。生成したコードそのものは返さず、
           書いたパスと内容の要約だけを一言で報告して。設計判断が必要な
           曖昧な点があれば、書く前に止めてその判断内容を報告して。"
}
```

生成されたコードは子エージェント自身がファイルへ書き込む。このスレッドの
コンテキストには一切乗らない。

## 落とし穴: model だけを指定しない

`spawn_agent` に `model` だけ渡して `reasoning_effort` を省略すると、
子エージェントの reasoning effort はその子のモデルの既定値へ静かに戻る
(親の設定を引き継がない)。毎回 `model` と `reasoning_effort` の両方を
明示すること。

## model フィールドが出てこない場合

インストール先の Codex ビルドによっては、`spawn_agent` のツールスキーマに
`model`/`reasoning_effort` が現れず、子エージェントが常に親と同じモデルを
継承することがある。その場合は `~/.codex/config.toml` に以下を追加すると
スキーマが開放される(未文書化の設定のため、バージョンによっては効かない
可能性がある):

```toml
[features.multi_agent_v2]
hide_spawn_agent_metadata = false
```

それでも `model` を指定できない、または指定すると弾かれる場合は、代わりに
セッション全体の既定委譲先を下げる機械レベルのバックストップを使う:

```toml
[agents]
default_subagent_model = "gpt-5.6-luna"
default_subagent_reasoning_effort = "medium"
```

これは `spawn_agent` 呼び出しのたびに毎回 `model` を書き忘れても、委譲先が
静かに高いモデルへ戻ってしまうのを防ぐ保険になる。

## 結果を待つとき

手元に並行してできる作業があるうちは待たない。子の最終回答はメールボックスに
届き、次のターンで自然に見える。本当に手が空いて結果待ちしかすることがない
場合のみ、`wait_agent` を 5〜10 分程度のまとまった単位で使う。短い間隔で
ポーリングしない — イベント購読なので、長く待っても短く待っても最初の
活動があった瞬間に起きる。
